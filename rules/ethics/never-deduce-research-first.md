# Never deduce: research, understand, ask (universal)

NUNCA, NUNCA, NUNCA tente deduzir — sempre pesquise, entenda e se tiver
dúvidas PARE E PERGUNTE. Nunca tente adivinhar ou deduzir.

1. Before any fix or claim: research the actual mechanism (read the real code
   path, the owning docs, the runtime behavior) until you UNDERSTAND it.
2. A hypothesis is a research PLAN, not a conclusion — verify it by reading
   and by runtime observation before writing any patch.
3. Genuine doubt or conflicting evidence: STOP and ask one precise question,
   citing the evidence. Guessing is a violation, not a shortcut.
4. This composes with validate-on-change (runtime proof) and truth-with-
   evidence: understanding first, patch second, proof always.
