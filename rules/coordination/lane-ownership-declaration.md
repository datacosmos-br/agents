# Declare and cooperate on lane ownership

Declare the current authorized scope, selected available tracker item, branch,
receiving integration base and PR identity through the selected coordination
channel before effects. A planned PR boundary may precede its creation. Tracker
selection and unavailable modes follow beads-traceability; create no substitute.

Before opening another lane, refresh the integration tip and inspect existing
PRs, branches, worktrees, ownership and WIP. Reuse work already present and
establish a coherent writing boundary with the current actor. Missing ownership
is an input to resolve while preserving the work, never permission to discard it.

Keep current evidence at effect, validation, publication and integration
boundaries under bead-branch-pr-cadence. A missing reply or elapsed interval does
not establish that another writer abandoned its work. Apply the selected
coordination owner's actual abandonment contract before ownership changes.

Adopt required work through the authorized reviewed integration path, preserving
commit history and attribution. The Git rule owns non-rewriting merges and
fast-forward pushes. Do not cherry-pick an active writer into a competing lane,
edit its worktree, rewrite its branch or silently supersede its authority. An
in-scope defect in adopted work is repaired jointly at its owner; provenance is
never a reason to leave the required result broken.

The 2026-10-20 operator-directed fix-forward/cooperation contract supersedes the
older immediate cherry-pick procedure. It grants no stall: continue independent
work in the same authorized unit, exchange concrete evidence and integrate the
complete dependency group. Ask only for an unresolved authority conflict or an
effect that requires new authorization.

Retirement requires the current Git and source-preservation proofs. Declaration,
publication, integration and installed runtime are distinct receipts.
