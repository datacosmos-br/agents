# Distribution System Gap Analysis & Remediation Plan

## Goal
Organize and improve the distribution system for agents, skills, rules, and commands
across project technology workspaces and for agents — fix the identified gaps so the
governance bundle and Kilo tooling config accurately reflect the current inventory
and enforce all ADR-defined contracts.

## Constraints
- ADR-0008: `GovernanceBundle` is the sole read-only semantic boundary; AI Hub owns
  runtime effects. This repo ships meaning only.
- Rule 5 (Root Make only): all checks run through selector-free Makefile verbs with `APPLY=Y`.
- Planning mode: no source mutations; this plan describes changes an implementation agent executes.

## Gap Inventory

### 1. Stale inventory counts in AGENTS.md (line 41)
- Claimed: "64 agents, 55 rules, 116 skills"
- Actual: 64 agents, 56 rules, 121 skills (`find` verified)
- Impact: misleading header; breaks trust in the canonical inventory.

### 2. Missing `propagate` Make target
- `CLAUDE.md` line 1: `@generated by ai-hub from config/workspaces.yaml; regenerate with make propagate APPLY=Y`
- Makefile `.PHONY` (line 19) and target list do **not** contain `propagate`.
- `config/workspaces.yaml` does not exist.
- Impact: generated CLAUDE.md cannot be regenerated; stale generation marker.

### 3. No managed-projection tool (ADR-0015 / distribution-routing.md)
- `rules/coordination/distribution-routing.md` Law 3 requires every projection to
  carry a `managed-by` marker + bundle version, and consumer surfaces to declare
  `retire:` globs.
- No tool in `tools/` implements `managed-by` injection or consumer `retire:` glob
  declaration. `render_waza_projection.py` only renders Waza eval YAML.
- Impact: projections cannot be version-swept; `retire:` globs have no schema.

### 4. Agent approval gap in `bundle.py`
- `bundle.py:75-95` — `_approved_artifacts` creates `ApprovedArtifact` entries for
  rules, skills, commands but **not agents**.
- `bundle.py:57` — `audit_precedence` is called with `_approved_artifacts(skills, commands, rules)`.
- Agents never participate in the precedence audit (supersedes resolution).
- Impact: agent `supersedes:` tags are never validated; old+new coexistence
  between agent profiles is undetectable.

### 5. Agent profile tag validation gap
- `agent_profiles.py:121-144` — `_validate_tags` only permits `activation:`, `mode:`,
  `detect:` tags. It never calls `resolve_approval_tags`.
- `commands.py:182`, `rules.py:263`, `catalog.py:168` all call
  `resolve_approval_tags(root, tags, path)` — agents are skipped.
- Impact: agents cannot carry `decision:`/`effective:`/`supersedes:` tags even if
  ADR-0008 says all semantic artifacts must carry approval lineage.

### 6. No `.kilo/` config structure
- Environment spec declares `.kilo/command/*.md`, `.kilo/agent/*.md`, `kilo.json`,
  and `AGENTS.md` should exist.
- `.kilo/` contains only an empty `plans/` directory.
- Impact: Kilo tooling has no command/agent definitions or `kilo.json` to load.

## Implementation Tasks

### Task 1 — Update AGENTS.md inventory counts
**Owner:** `AGENTS.md:41`
**Action:** Change `64 agents, 55 rules, 116 skills` to `64 agents, 56 rules, 121 skills`.
**Verify:** `make audit APPLY=Y` prints the correct counts.

### Task 2 — Add `propagate` Make target + `config/workspaces.yaml`
**Owner:** `Makefile`, `config/workspaces.yaml` (new), `CLAUDE.md` (regenerate marker)
**Action:**
1. Create `config/workspaces.yaml` — a declarative mapping of workspace
   configurations (project tech stacks → skill selectors) consumed by `propagate`.
   Schema: `version: 1`, `workspaces:` list with `name`, `path`, `subjects`,
   `retire_globs`.
2. Add `propagate` to the Makefile `.PHONY` line and define a target:
   ```makefile
   propagate: ## regenerate AI Hub project configuration; requires APPLY=Y
       $(call REQUIRE_APPLY)
       $(call BANNER,propagate · project surface configuration)
       @uv run python tools/render_project_projection.py
   ```
3. Create `tools/render_project_projection.py` — reads `config/workspaces.yaml`,
   loads `GovernanceBundle.load()`, injects `managed-by` marker + bundle version,
   applies `retire:` globs from the workspace config, writes to the target
   project surface. Follows the same strict subprocess/lock pattern as
   `render_waza_projection.py`.
4. Add `managed-by` marker constant to the projection tool (bundle version injected
   from `GovernanceBundle.distribution_version`).
**Verify:** `make docs APPLY=Y` passes (audit step confirms bundle integrity).

### Task 3 — Agent approval integration
**Owner:** `src/agents_governance/agent_profiles.py`, `src/agents_governance/bundle.py`
**Action:**
1. In `agent_profiles.py`, update `_TAG_NAMESPACES` equivalent to include
   approval namespaces from `APPROVAL_NAMESPACES` (imported from `approvals.py`).
   Agent profiles must call `resolve_approval_tags(root, tags, path)` during audit.
   Add `decision:` + `effective:` validation to `_validate_tags`.
2. In `bundle.py`, add agents to `_approved_artifacts`:
   ```python
   *(
       ApprovedArtifact(f"agent:{agent.name}", agent.tags, agent.path)
       for agent in agents
   ),
   ```
3. Add existing agent profiles' `decision:` and `effective:` tags. Each agent
   profile under `agents/agent-wide/` and `agents/project-wide/` is missing
   approval lineage. Add `decision:ADR-0008` and `effective:2026-09-07` (or
   latest effective date from the ADR) to every agent's `metadata.aihub.tags`.
   **Note:** This requires adding `decision:` and `effective:` to the
   `_VALID_FIELDS` in `agent_profiles.py` (currently only `activation:`, `mode:`,
   `detect:` are allowed).
**Verify:** `GovernanceBundle.load()` succeeds; `bundle.agents` count > 0;
`audit_precedence` runs over all four artifact types.

## Data Flow

```
config/workspaces.yaml → render_project_projection.py → GovernanceBundle.load()
                                      ├─ managed-by marker (distribution_version)
                                      ├─ retire: globs sweep
                                      └─ route:/subject:/detect: routing
                                      ↓
                              project .agents/ surface
```

Current gap: `render_waza_projection.py` only does eval projections; the new
`render_project_projection.py` fills the managed projection gap for skills/rules/
commands/agents → `.agents/` homes.
