# ADR-0006 — Synthesize historical governance by behavior, not structure

- **Status:** Accepted
- **Date:** 2026-08-28
- **Scope:** External or historical rules, skills, commands, and generated agent surfaces
- **Relates to:** ADR-0001, ADR-0002, ADR-0003, and ADR-0005

## Context

The supplied historical corpus contains old canonical sources, provider
projections, command wrappers represented as skills, generated optimization
staging, generic ecosystem guidance, and several focused procedures with useful
behavior. Importing directories or identities would restore multiple owners,
obsolete runtimes, provider assumptions, and contradictory failure semantics.

The useful gaps are behavioral: structured brand discovery, evidence-based
competitive analysis, adversarial implementation-plan review, dynamic-reference
safety during refactoring, and process-provenance diagnosis for agent loops.

## Decision

External and historical artifacts are read-only evidence. Each relevant bundle
is inspected with its resources and reduced to outcome, activation boundary,
inputs, effects, failure behavior, scope, current consumer, provenance, license,
and material proof. The resulting statements are placed through the artifact
boundaries in ADR-0001 and the single-owner rule in
`rules/architecture/governance-artifact-composition.md`.

The current catalog absorbs the useful behavior as follows:

| Historical behavior | Canonical disposition |
|---|---|
| Multi-session brand identity interview | New `brand-discovery` skill; persistence requires an operator-approved destination |
| Competitor scoping, benchmarking, and report assembly | One configurable procedure owned by `market-research` |
| Plan grilling and senior review | New `implementation-plan-review` skill composed with `product-capability` and `search-first` |
| Graph-assisted dead-code and rename checks | Generalized dynamic-reference gate owned by `dry` |
| Agent fleet and loop diagnosis | Metadata-safe process forensics owned by `agent-introspection-debugging` |
| Repeated external-corpus adoption | Explicit `synthesize-governance` command composed with governance skills and rules |

No fixed scoring dimensions, tool quota, coverage percentage, framework choice,
private path, provider command, updater, or historical runtime becomes universal
policy. The canonical source has no runtime dependency on the supplied corpus.

## Rejected families

- provider projections, caches, backups, and optimization staging;
- command wrappers, compatibility skills, and alternate agent-runtime facades;
- unconditional tracker/orchestrator workflows while those capabilities are
  suspended or unselected;
- language/framework matrices that mandate tools, libraries, versions, layouts,
  or thresholds not selected by the current project;
- catalog indexes, token dashboards, and design micro-skills without a distinct
  current consumer;
- fallback, retry, normalized failure, partial execution, compatibility, or
  copied generated output.

## Consequences

The catalog grows only for distinct recurring capabilities and explicit command
grammar with current consumers. Existing owners gain focused references and
semantic evaluations. Inventory totals are derived from the current canonical
sources and generated lock; no numeric acceptance cap governs later additions.
Generated inventories and provider surfaces remain projections, and the
historical corpus may be removed independently without affecting runtime.
