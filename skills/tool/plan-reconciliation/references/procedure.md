# Sequential plan reconciliation

## Admit the configured corpus

Resolve the authorized project set, declared dependency graph, versioned plan
destination, optional home projection, provider adapters, document owners, integration
lanes, and selected tracker runtime from current configuration. Missing or contradictory
ownership stops admission; no guessed directory or substitute tracker is created. An
operator can name a project in ordinary language; the automation resolves its configured
identity.

Use only authorized collection and documentation operations through their declared
verbs. Read their effects before invocation; a documentation verb may write output.
Do not enable publication of private sources merely to inventory existing local plans.
Enabled adapters discover and extract their declared provider sources, including
unexported sessions and referenced attachments. Validate the complete inventory against
the [source contract](input-contract.md). Do not ask the operator to curate exports that an
enabled adapter owns. A missing provider capability, unreadable source, parse warning,
truncated payload, or absent attachment is an explicit collection failure, never an
empty provider or a successful partial corpus.

Inventory metadata is not an execution ledger. It identifies evidence and coverage;
Beads alone owns priority, active work, blockers, and closure. During tracker
suspension, follow the existing suspension boundary and do not invent an alternative
status file.

Before semantic transfer, align the affected canonical documentation and governance
under `rules/workflow/living-documentation.md`. Resolve the AI Hub Beads-to-TODO contract
through `rules/workflow/beads-traceability.md`; its real automation is a prerequisite
before retirement relies on that view. A missing capability requires a bounded owner
repair decision, not manual TODO generation, another collector or an ad-hoc script.

For handwritten TODO adoption, transfer every unique item/prose semantically into
Beads/docs with per-item receipts before replacement. The 2026-10-23T21:26:27Z
operator correction selects Git history for old TODO versions/data; record committed
revision/path rather than creating a parallel backup/archive store or TODO backup
writer. Unique untracked/uncommitted content remains in place until accounted for;
never claim Git history recovers it or create automatic commits. Publication safety
and CAS requirements are unchanged. The protected-evidence rules below still apply
to unrelated plan attachments and private evidence.

## Select and read one plan

Publish the index in ascending order of evidenced last update, represented in UTC
ISO 8601. Evaluate it bottom-up: select the newest plan first, then advance toward older
plans only after closure. Index order and execution order are distinct contracts. Retain
the original timestamp, its source, and observation time. Filesystem mtime is an
observed revision signal, not proof of authored decision time. Do not fabricate a date
for an undated plan. Resolve ambiguous precedence before semantic effects; deterministic
identifier order is only an inventory tie-break.

Resume an already active plan before selecting another, unless the newest operator
instruction replaces it. Read its entire source, companion directory, research, addenda,
referenced documents, and attachments to completion. Follow provenance links to older
correlated plans when establishing changed direction. A clipped handoff or search
excerpt cannot substitute for full reading.

Delegate bounded evidence gathering and simple changes only within this active plan. The
orchestrator owns semantic adjudication, review, and integration. Do not start the next
plan's reconciliation while the current plan is open.

## Reconcile intent against reality

For each affected project, work from dependency owners toward consumers using the
configured graph, one project at a time. A cycle or unknown dependency is a
configuration question, not permission to guess a layer order.

Compare current operator intent, the plan's dated decisions, all correlated open and
closed Beads, canonical configuration/models/generators, public consumers, integration
history, maintained code, and measured behavior. Use current graph relationships only
after establishing freshness through their owner, and verify them in source. Use the
composed parents for their evidence and artifact contracts. Explain exactly which newer
instruction superseded which older direction. Distinguish implemented behavior,
unimplemented intent, superseded guidance, and a false premise; a timestamp, similarity
score, or closed bead cannot make that decision. Classify each claim as valid guidance,
implemented with current evidence, superseded with a named newer decision, pending, or
invalid with rationale. Implemented-but-unvalidated is not proven runtime behavior.

Update the selected Beads with evidence and correct relationships, including closed
records where the current facts differ. Link plans, beads, current docs, and ADRs
bidirectionally where their owners support links. Record dispositions on the selected
Bead, not by rewriting the historical plan into a second task-status authority. Reuse
existing issues after semantic review; preserve the original claim, acceptance conditions
and source identity when transferring valid unimplemented work. Leave that work open;
neither retiring a plan nor completing its reconciliation closes implementation issues.

Transfer useful statements FIRST to the smallest maintained owners: README/guides for
usage, AGENTS/rules/skills for procedure, ADRs for decisions, public docstrings for
observed contracts, and Beads for pending executable work. Describe pending targets as
pending, never as live behavior. AI Hub derives TODO entries from canonical issues under
the tracker rule; do not manually transfer work into generated Markdown. Research,
addenda and attachments remain evidence until their unique content has a protected or
maintained destination proved under the source contract. Do not create a live archive
of retired plans. Update affected ADRs in place only for a real changed decision, with
the dated change explanation immediately below the changed decision. For
duplicate ADRs about the same decision in the same scope, retain the oldest ADR
identity, incorporate useful newer text there, and record the dated explanation directly
below the altered decision. Replace the newer duplicate with a reference to that
surviving ADR and rewire its consumers. Chronology selects the stable identity, not
stale decision content: newer authorized intent still governs. Distinct decisions or
scopes remain separate. Reconcile applicable skill/command/rule owners and their
consumers through AI Hub's existing distribution transaction.

Do not delete a source because it resembles another. Only the orchestrator can
adjudicate a completely superseded document with no unique remaining evidence;
retirement additionally needs the authorized destructive scope and provenance proof.
Historical material stays evidence, never a revived instruction. Do not implement a
plan's pending product proposals during reconciliation. If machinery cannot perform an
approved operation, record the causal defect and obtain bounded authorization before
code work. For authorized repairs, consult and update docs first, exercise the real
public runtime, and change tests last under the existing engineering and testing rules.

## Validate, retire and advance

Validate the active plan's changed documentation, links, executable snippets, tracker
relationships and required distribution boundaries through current canonical verbs.
For separately authorized code repairs, follow their applicable native gates only after
real runtime proof. Publish short recoverable checkpoints only when separately
authorized, through the declared Git/PR owners; this procedure grants no automatic Git
action, service restart or distribution effect.
The home copy is a configured projection of the versioned corpus, not a second writer.
Use the owning generator for resources, renames, and stale managed targets; prove its
fixed point.

Before exact-path retirement, account for every claim and attachment, prove durable
destinations for all useful content and valid pending work, rewire backlinks, and record
the source identity/revision, reasoned dispositions, destinations and validation on the
reconciliation Bead. Preserve unique private evidence under its approved protected owner;
a digest cannot recover lost bytes. Compose `safe-delete` for literal targets and
recovery, never a glob or directory sweep. Re-read source revisions and shared
destinations immediately before deletion; changed input invalidates its earlier
adjudication until reconciled, without requiring a clean or frozen shared worktree.

Keep this plan active through its required review, approval, publication, installed
propagation, retirement diff, link checks and TODO/Beads agreement receipts. Record
reconciliation completion separately from still-open implementation work through the
existing closure owner, then advance. A missing attachment, unreadable source,
incomplete transfer, unknown disposition, unresolved question or failed publication holds
this plan active. On interruption preserve the exact plan, completed transfers, remaining
questions, first failure and next action in Beads. Refresh inventory and operator
corrections after every plan. Retire the controlling plan only after its procedure and
recovery context have durable owners.
