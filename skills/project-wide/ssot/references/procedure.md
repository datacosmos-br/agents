# SSOT authority and convergence procedure

## Absolute authority law

Each mutable concept in the authorized affected graph has one writable authority.
The authority owns validation, types, defaults, invariants, and lifecycle. All
other forms are derived or consuming surfaces and must be unable to override it.

Multiple readers are normal; multiple independent writers or default owners are
split brain. A script that periodically reconciles two writable truths, a fallback
constant beside config, a test fixture copied from a mutable default, or prose that
redeclares a configurable value is not resilience. It is an authority defect with
runtime drift and data-loss risk.

## Flow contract

The canonical sequence lives in `search-first`; do not reproduce it here. Consume
its discovery packet after `yagni`, output one authority map to `solid`,
implementation, and `dry`, then accept one post-rewiring convergence recheck.
SSOT owns only authority topology and projection convergence; it does not decide
necessity, responsibility boundaries, structural cleanup, or local code form.

## Build the authority map

For every affected fact or contract, identify:

- its current requirement, canonical type/schema, validation, and precedence;
- every writer, mutation API, default, loader, generator, migration, and override;
- every reader, caller, public runtime path, test, document, and external consumer;
- which artifact is source, generated projection, read-only mirror, cache, or
  observational evidence;
- the declared owner and the decisive project authority that makes it canonical;
- the native generation, comparison, runtime, and gate commands.

Read definitions and construction paths, not names alone. Generated markers,
repository rules, schemas, write permissions, and actual runtime wiring outrank a
comment claiming “source of truth.” History explains drift but is never an active
authority. If two sources both claim precedence and no higher contract resolves
them, block and request that exact ownership decision; never guess.

## Select one owner without inventing one

Prefer the project's declared typed facade, schema, config, manifest, catalog, or
generator input that already owns the concept and is used by the real consumer.
The selected owner must be writable through the supported mutation path, validate
all inputs once, and represent every current required case.

Do not select a generated file, cache, report, test, documentation page, runtime
observation, remote mirror, or convenient local copy as the authority when an
upstream owner exists. Runtime is the behavioral reality used for verification;
it does not authorize reverse-engineering mutable configuration into a second
owner. Tests derive expectations from inputs or round-trip the real owner.

If no established owner can satisfy the current contract, select the smallest
typed authority consistent with the existing architecture and approved current
consumer, then let SOLID validate its responsibility and dependency boundary.
YAGNI forbids a generic registry, compatibility layer, or future synchronization
plane.

## Complete the cutover atomically

1. Protect the real public behavior, causal failures, precedence, and invariants.
2. Move validation, types, defaults, and writes into the selected authority.
3. Make generators deterministic functions of that authority. Publish projections
   atomically and mark them non-authoritative.
4. Rewire every current reader and writer to the supported facade or projection.
5. Remove duplicate constants, schemas, defaults, writers, overrides, loaders,
   dual reads/writes, fallback precedence, compatibility aliases, stale fixtures,
   copied examples, and mutable values embedded in docs.
6. Make obsolete formats fail explicitly. Never leave old and new authority paths
   coexisting or add reconciliation glue between them.
7. Use `dry` for structural consolidation and deletion across files, then apply
   `simplify` to every changed unit. Recheck YAGNI, this authority map, and SOLID.

Documentation names the owner and stable config keys or contracts; it does not
duplicate mutable values. A projection can be committed only when the repository
declares that contract and its generator proves convergence.

## Convergence and runtime proof

Run the real consumer before general tests, again after rewiring, and on the
integrated result. Exercise both valid input and invalid/removed paths so no
fallback silently wins.

Run the canonical generator twice from unchanged input. The second run must make
zero changes. Compare source-to-projection semantics, not timestamps or incidental
formatting. Then run native unit, integration, static, type, build, security,
dependency, generation, and projection gates for the affected scope.

Search again for every removed writer, default, schema, literal, old key, and
construction path. Report the selected authority, its decisive evidence, roles of
all projections/consumers, removed competitors, consumers rewired, two-run fixed
point, runtime commands, gates, and any unresolved ambiguity. Never claim SSOT
from file naming, documentation, or a green test alone.
